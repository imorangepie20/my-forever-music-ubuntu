# 기분 기반 추천 페이지 설계

## 목표

사용자가 지금 듣고 싶은 기분과 예시 곡 몇 개를 입력하면, 기존 GMS preview API를 통해 바로 추천곡을 받아볼 수 있는 사용자용 페이지를 만든다.

## 사용자 흐름

1. 사용자는 사이드바의 `지금 내 기분은...` 메뉴로 이동한다.
2. `집중`, `차분`, `신남`, `쓸쓸함`, `새 발견` 중 하나를 고른다.
3. 예시 곡을 한 줄에 하나씩 입력한다. 권장 형식은 `곡명 - 아티스트`다.
4. 추천 개수(10/15/20곡)와 에너지 기준을 선택하고 `추천받기`를 누른다.
5. 결과 곡은 카드로 표시되고, 사용자는 곡 하나를 재생하거나 전체 추천 결과를 큐로 재생할 수 있다.

## 데이터 흐름

- 프론트는 새 API를 만들지 않고 `previewGmsRecommendations`를 사용한다.
- 사용자가 입력한 예시 곡 텍스트는 `seed_track_ids`로 전달해 요청 context에 남긴다.
- `곡명 - 아티스트` 형식에서 추출한 아티스트명은 `seed_artist_names`로 함께 전달해 현재 GMS affinity 계산에 실제로 반영한다.
- 예시 곡 정규화와 track id 승격은 후속 단계의 별도 검색/정규화 API에서 처리한다.

## UI 원칙

- 이 페이지는 운영자 검토 화면이 아니라 사용자 추천 진입점이다.
- 내부 점수와 gate dry run 같은 운영자 문구는 노출하지 않는다.
- 결과는 “지금 들을 곡” 중심으로 보여주고, 경고가 있으면 사용자에게 필요한 수준으로만 표시한다.

## 검증

- `sitewide-korean-product-language-harness`에서 페이지 존재, 핵심 한글 문구, GMS preview API 연결을 확인한다.
- AI preview 운영 프로세스가 구버전 schema로 떠 있어도 422가 나지 않도록 사용자 페이지의 추천 개수는 20곡 이하로 제한한다.
- `npm run test:product-language`, `npm run lint`, `npm run build`로 검증한다.
