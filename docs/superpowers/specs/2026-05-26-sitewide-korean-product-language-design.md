# 사이트 전체 한국어 제품 언어 정비 설계

작성일: 2026-05-26

## 목적

이제 사이트에는 실제 음악 제품 화면이 충분히 쌓여 있어서 특정 페이지의 문구만 고치는 방식으로는 부족하다. `/gms-preview`에서 드러난 핵심 문제는 추천 용어, 운영자 진단, 사용자 설명, 가져오기/재생/저장 액션이 사이트 전체에서 같은 한국어 제품 언어로 정리되어야 한다는 점이다.

이번 작업은 실제 음악 서비스 경험에 대한 사이트 전체 한국어 제품 언어 1차 정비를 정의한다. 다국어 전환이나 i18n 인프라를 도입하지 않는다. 목표는 한국어 사용자가 화면의 목적과 다음 행동을 바로 이해하는 것이다.

## 범위

### 포함

- 메인 내비게이션과 헤더 문구
- 홈 화면의 음악 섹션
- 로그인/회원가입 화면
- 플랫폼 연결과 OAuth callback 화면
- PMS 화면: 내 음악 보관함, PMS 플레이리스트 상세, 저장/가져오기 흐름
- EMS 화면: 탐색, 검색 플레이리스트 상세, 수집 플레이리스트 상세
- GMS 화면: 추천 플레이리스트, 추천 미리보기/검토 화면
- 아티스트 상세 화면
- 멜론 Hot 100 화면과 재생 안내
- 추천 알고리즘 설명 화면
- 공통 플레이어와 음악 카드 라벨
- 현재 관리자 계정에 노출되는 운영 화면
  - 스케줄 관리
  - EMS 수집
  - EMS 큐
  - 추천 품질
  - 특성 커버리지
  - SASRec 모델
  - 메타데이터 정규화

### 제외

- 전체 i18n 프레임워크나 언어 전환 기능
- 현재 음악 제품이 아닌 템플릿/데모 화면
  - dashboard 템플릿
  - email 화면
  - POS 화면
  - 일반 UI/forms/tables 예제
  - product/pricing/profile/calendar/gallery 데모 화면
- backend error payload의 한국어화
- 추천 순위 계산 방식 변경
- 문구 위계와 설명 블록을 넘어서는 새 시각 디자인 개편

제외된 템플릿/데모 route는 별도 정리 작업으로 다룬다. 이후 navigation에서 숨기거나, 사용하지 않는 route를 제거하거나, 실제 제품 화면으로 재활용할 수 있다.

## 제품 언어 규칙

### 도메인 용어

아래 라벨을 일관되게 사용한다.

- PMS: `내 음악 보관함(PMS)`
  - 의미: 사용자가 소유하는 음악 라이브러리이자 장기 취향 기준
- EMS: `음악 탐색 풀(EMS)`
  - 의미: 외부 공개 플레이리스트, 트렌드, 탐색 후보가 모이는 공간
- GMS: `추천 게이트(GMS)`
  - 의미: 사용자 취향 모델을 통과한 추천 결과가 모이는 공간

공간이 좁은 UI에서는 아래 축약형을 사용한다.

- `내 음악(PMS)`
- `탐색 풀(EMS)`
- `추천(GMS)`

### 핵심 액션

- `Import`: `가져오기`
- `Connect`: `연결하기`
- `Preview`: `미리보기`
- `Save`: `저장하기`
- `Like`: `좋아요`
- `Pass`: `넘기기`
- `Play`: `재생`
- `Play all`: `전체 재생`
- `Open`: `열기`
- `Retry`: `다시 시도`
- `Refresh`: `새로고침`
- `Approve`: `승인`
- `Reject`: `거절`
- `Resolve`: `해결`

### 추천 신호

사용자에게 보이는 설명은 기술 토큰보다 음악적 이유를 먼저 말한다.

- `취향과 얼마나 가까운지`
- `최근 듣던 흐름과 얼마나 다른지`
- `플레이리스트 안에서 분위기가 자연스러운지`
- `아티스트와 장르가 한쪽으로 치우치지 않는지`
- `이미 비슷한 곡이 너무 많지 않은지`
- `추천에 필요한 단서가 충분한지`

아래 기술 라벨은 운영자 진단 영역 안에서만 그대로 노출할 수 있다.

- `affinity`
- `novelty`
- `coherence`
- `diversity`
- `redundancy`
- `confidence`
- `gate`
- `dry run`
- `rank delta`
- `taste mode affinity`

기술 라벨을 보여줄 때는 반드시 한국어 라벨이나 설명을 함께 붙인다.

## 운영자 진단 패턴

추천 모델의 기술 근거는 일반 사용자 안내처럼 보이면 안 된다.

일관된 블록 라벨을 사용한다.

`운영자 전용 진단`

짧은 안내 문구를 함께 표시한다.

`추천 모델과 게이트 상태를 점검하기 위한 정보입니다. 일반 사용자가 선택해야 하는 항목은 아닙니다.`

이 블록에는 raw score, gate 상태, 순위 변화, 출처 근거, backend token을 포함할 수 있다. 단, 시각적으로 보조 정보처럼 보여야 하며 사용자용 추천 이유 뒤에 배치한다.

## 페이지 설명 패턴

실제 서비스 화면은 긴 튜토리얼 없이 아래 세 가지 질문에 답해야 한다.

1. 이 화면은 무엇을 하는 곳인가?
2. 사용자는 다음에 무엇을 하면 되는가?
3. 이 행동이 PMS, EMS, GMS 또는 취향 모델에 어떻게 연결되는가?

설명은 짧고 밀도 있는 블록으로 제공한다. 운영성 화면에서는 마케팅형 hero section을 만들지 않는다.

### 예시

#### GMS 추천 검토

목적:

`PMS 보관함과 EMS 후보를 비교해 지금 저장하거나 들어볼 만한 추천 곡을 검토합니다.`

흐름:

`기준 선택 -> 추천 미리보기 생성 -> 후보 듣기/좋아요/넘기기/저장 -> PMS 취향 신호에 반영`

#### PMS

목적:

`연결한 스트리밍 플랫폼에서 가져온 플레이리스트와 사이트에서 저장한 추천곡이 모이는 개인 음악 보관함입니다.`

흐름:

`플랫폼 연결 -> 플레이리스트 가져오기 -> 오디오 특성 보강 -> 취향 모델 학습`

#### EMS

목적:

`외부 공개 플레이리스트와 트렌드에서 새로운 추천 후보를 찾는 탐색 공간입니다.`

흐름:

`검색/수집 -> 후보 확인 -> 재생/상세 확인 -> GMS 추천 후보로 활용`

## 내비게이션과 route 정책

사용자에게 보이는 navigation은 실제 음악 제품에 집중한다.

- 홈
- 플랫폼 연결
- 내 음악(PMS)
- 음악 탐색(EMS)
- 추천 플레이리스트
- 추천 검토(GMS)

관리자 navigation은 관리자 계정에만 노출하고 한국어 라벨을 사용한다. test/harness 화면은 일반 사용자 경로처럼 강조하지 않는다. route가 남아 있어야 한다면 테스트 또는 진단 목적임을 라벨에 명확히 표시한다.

제품과 무관한 템플릿/데모 화면은 primary navigation에 추가하지 않는다. 이후 별도 정리 작업에서 사용하지 않는 import와 route를 제거하거나 숨긴다.

## 구현 경계

이번 작업은 full translation framework보다 local copy constant와 작은 shared helper를 우선한다.

권장 shared helper:

- 반복 라벨을 담는 product glossary module
- 추천 신호 라벨 mapper
- 재사용 가능한 운영자 진단 header 또는 compact component

UI 문구를 한국어로 바꾸기 위해 API contract를 변경하지 않는다. backend token은 UI 코드에서 한국어 라벨로 mapping한다.

## 검증

검증에서는 아래 항목을 확인한다.

- app build가 통과한다.
- 주요 제품 route가 한국어 page title과 핵심 action을 렌더링한다.
- `/gms-preview`에서 사용자용 추천 이유와 운영자 진단이 분리된다.
- 관리자 전용 화면은 관리자/운영자 화면임을 명확히 표시한다.
- 템플릿/데모 화면이 primary navigation으로 승격되지 않는다.
- 영어 기술 token은 진단 가치가 있는 곳에만 남고 한국어 맥락을 함께 가진다.

권장 확인:

- `npm run build` in `apps/web`.
- 기존 test infrastructure가 지원하면 주요 화면 text assertion을 추가한다.
- 포함 범위의 route를 수동으로 한 번 훑는다.

## 수용 기준

- 한국어 사용자가 개발자의 설명 없이 PMS, EMS, GMS 화면의 목적을 이해할 수 있다.
- 추천 카드는 raw model detail보다 한국어 추천 이유를 먼저 설명한다.
- 운영자 전용 데이터는 운영자 진단으로 명확히 표시된다.
- 같은 핵심 action은 사이트 전체에서 같은 한국어 동사를 사용한다.
- 데모/템플릿 화면은 이번 작업의 제외 범위로 문서화되고 제품 화면으로 취급되지 않는다.
