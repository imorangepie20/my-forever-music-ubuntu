Ubuntu SSH Server Design

Project: my-forever-music · 작성일: 2026-05-19 · 대상 서버: Ubuntu host jo-ROG-server

1. 목적

이 문서는 MacBook 또는 외부 개발 장비에서 Ubuntu 서버로 안정적으로 원격 접속하기 위한 SSH 서버 설정 기준을 정의한다. 현재 서버는 my-forever-music의 API, AI, Web, Nginx, PostgreSQL, Redis를 실행하는 개발/이전 검증 환경이므로 SSH 설정은 운영 중인 서비스를 끊지 않는 방향을 우선한다.

핵심 원칙: 처음에는 비밀번호 로그인을 유지해서 잠금 위험을 낮추고, 공개키 접속을 검증한 뒤에만 비밀번호 로그인을 끈다.

2. 범위

포함 openssh-server 설치 확인, host key 생성, ssh.socket 포트 설정, sshd_config drop-in 관리, ufw SSH 허용, 설정 검증과 롤백
제외 VPN, bastion host, fail2ban, 2FA, cloud provider security group, 정식 운영 계정 분리 정책
관리 스크립트 infra/scripts/setup-ubuntu-ssh-server.sh

3. 현재 접속 모델

Antigravity 리모트 세션은 이미 MacBook에서 Ubuntu 호스트로 연결된 상태다. 다만 이 연결이 반드시 일반 SSH 22/tcp를 그대로 사용하는 것은 아닐 수 있다. 따라서 일반 터미널 SSH 접속은 별도로 검증한다.

Ubuntu LAN IP 192.168.219.150
기본 사용자 jo
내부 접속 확인 ssh -p 22 jo@127.0.0.1
MacBook LAN 접속 ssh jo@192.168.219.150
외부 인터넷 접속 공유기에서 TCP 22 -> 192.168.219.150:22 포워딩 필요

4. 설계 결정

4.1 systemd socket activation 유지

Ubuntu 24.04 계열에서는 OpenSSH가 ssh.socket으로 listen하고 요청 시 ssh.service를 트리거할 수 있다. 이 환경에서는 ssh.service가 평소 inactive로 보일 수 있으므로, active 여부 판단은 ssh.socket과 실제 listen 포트를 함께 본다. 

systemctl status ssh.socket --no-pager -l
ss -tlnp | grep -E ':22\b'

4.2 IPv4와 IPv6 listen 명시

connection refused를 피하기 위해 socket override에 IPv4와 IPv6를 모두 명시한다. 

[Socket]
ListenStream=
ListenStream=0.0.0.0:22
ListenStream=[::]:22
BindIPv6Only=ipv6-only

4.3 OpenSSH 설정은 drop-in으로 관리

기본 /etc/ssh/sshd_config는 최대한 보존하고, 프로젝트 관리 설정은 /etc/ssh/sshd_config.d/01-my-forever-music.conf에 둔다. OpenSSH는 먼저 읽힌 설정 값이 우선되는 항목이 있으므로 파일 번호는 앞쪽으로 둔다.

4.4 검증 실패 시 롤백

스크립트는 SSH 설정 파일과 socket override를 수정하기 전에 임시 백업을 만들고, sshd -t 또는 재시작 과정에서 실패하면 이전 상태로 복구한다.

5. 기본 보안 정책

Port 22
PubkeyAuthentication yes
PasswordAuthentication yes 기본 유지. 공개키 접속 확인 후 no로 전환
KbdInteractiveAuthentication PasswordAuthentication과 같은 값으로 설정
PermitRootLogin prohibit-password
X11Forwarding no
ClientAliveInterval 300
ClientAliveCountMax 2
주의: --disable-password는 authorized_keys가 비어 있으면 실행하지 않는다. 접속 중인 세션을 닫기 전에 반드시 다른 터미널에서 새 SSH 로그인을 확인한다.

6. 실행 절차

6.1 SSH 서버 기본 설정

cd /srv/my-forever-music
./infra/scripts/setup-ubuntu-ssh-server.sh

6.2 공개키 등록

공개키는 접속할 클라이언트 장비에서 만든 값을 사용한다. 서버에 ~/.ssh/id_ed25519.pub가 없으면 --authorized-key-file은 실패하는 것이 정상이다. 

./infra/scripts/setup-ubuntu-ssh-server.sh \
  --authorized-key 'ssh-ed25519 AAAA...'

6.3 비밀번호 로그인 비활성화

./infra/scripts/setup-ubuntu-ssh-server.sh --disable-password

7. 검증 기준

  1. ssh.socket이 active 상태다.
  2. ss -tlnp에서 0.0.0.0:22와 [::]:22가 보인다.
  3. 서버 내부에서 ssh -p 22 jo@127.0.0.1 실행 시 connection refused가 아니다.
  4. MacBook에서 ssh jo@192.168.219.150가 인증 단계까지 도달한다.
  5. 외부 도메인 접속이 필요하면 공유기 포트포워딩 후 같은 검증을 반복한다.
./infra/scripts/setup-ubuntu-ssh-server.sh --check-only
ssh jo@192.168.219.150

8. 장애 판단표

증상 해석
Connection refused 대상 주소/포트에 SSH가 listen하지 않거나, 포워딩이 다른 곳을 보고 있다.
Permission denied SSH 서버는 열려 있고 인증 단계에서 실패했다. 비밀번호나 공개키를 확인한다.
Missing privilege separation directory: /run/sshd /run/sshd가 없다. 스크립트가 install -d -m 0755 /run/sshd로 생성한다.
sshd: no hostkeys available host key가 없다. ssh-keygen -A로 생성한다.

9. 운영 메모

  • SSH 설정 변경은 서비스 배포 스크립트와 분리한다.
  • API/Web/AI 재시작은 restart-ubuntu-stack.sh에서 관리한다.
  • SSH 포트를 바꾸면 공유기 포트포워딩과 ufw 규칙도 함께 바꾼다.
  • 비밀번호 로그인을 끈 뒤에는 새 장비 접속을 위해 공개키 등록 절차를 먼저 준비한다.
